# Kings Equestrian — Trainer & Stable Manager Guide  
## How to use the Stable Management app

**Who this is for:** Trainers, stable managers, grooms, and yard staff who run daily operations  
**What this app does:** Sessions, staff attendance, horses, feed, tack, and a full activity history — all in one place on phone or computer

---

## 1. Getting started

### 1.1 Open the app

1. Use the **web link** your admin gave you (campus-specific — do not share across cities).
2. Sign in with your **username** and **password** (from the admin / TRAINERS sheet).
3. If you see “session expired”, sign in again.

### 1.2 Tabs (left to right)

| Tab | Use it for |
|-----|------------|
| **Dashboard** | Morning overview — who’s in, alerts, low stock, overdue horse care |
| **Sessions** | Today’s classes, attendance, booking new classes |
| **Staff** | Who came to work, leave, staff details |
| **Riders** | Rider list, progress, search |
| **Feed** | Hay, oats, supplements — stock in, daily use, counts |
| **Tack** | Saddles, bridles, helmets — stock, damage, transfers |
| **Horses** | Horse register, vaccination/farrier, extra care, lease |
| **History** | Search everything that happened (last 30 days by default) |

**Tip:** After you change something, use **↻ Refresh** on that tab if numbers look old. Switching away and back usually reloads from cache; Refresh forces the latest data.

---

## 2. Daily routine (recommended)

Do these every working day:

| When | Tab | Action |
|------|-----|--------|
| **Start of day** | Dashboard | Check alerts (care overdue, low feed, staff, sessions) |
| **Start of day** | Staff | Confirm everyone is **Present**; tap **Absent** only for people who did not come |
| **Before / after lessons** | Sessions | Mark rider **Present** or **No-Show**; add reflection notes if needed |
| **End of day** | Feed | For each **Regular** feed item → **Log today** (how much was used) |
| **When something happens** | Horses | Log care (vaccination done, farrier, shoeing…) or lease change |
| **When stock moves** | Feed / Tack | **Stock in** (delivery) or **Wear out** / **Expire** as needed |
| **Weekly** | Dashboard | Scan care overdue and “needs confirm” feed banners |

## 3. Dashboard

**Purpose:** One-screen health check.

**What you see:**
- Riders scheduled vs present today  
- Horses and staff counts  
- **Alerts** — red/amber boxes (care overdue, feed low, stock count needed, tack out of stock, etc.)

**Actions:**
- Read alerts → tap the tab mentioned in the message (Feed, Horses, Staff…).  
- **Refresh** — top-right ↻ on Sessions header also refreshes date label; use Dashboard **Refresh** button at bottom of dashboard cards.

**You do not add data on Dashboard** — it only shows summaries.

---

## 4. Sessions

**Purpose:** Run the day’s riding classes.

### 4.1 View sessions

- **Today** / **Tomorrow** / **Custom date** at the top.  
- List shows riders, time, attendance status.

### 4.2 Mark attendance

1. Find the rider/session row.  
2. Mark **Present** or **No-Show** (wording may show as attendance chips/buttons on the card).  
3. Changes save to the schedule.

### 4.3 Book a new class

1. Open **Book class by grade & section**.  
2. Choose **Single date** or **Recurring weekly**.  
3. Pick grade, section, start/end time, date(s).  
4. Preview riders → **Schedule class**.

Use recurring for the same weekday pattern across a month range.

### 4.4 Group actions (Add / Move / Class / Cancel)

On each session group card:

| Button | What it does |
|--------|----------------|
| **+ Add** | Add late joiners (same grade & section) |
| **↪ Move** | Move the whole group to another date/time |
| **↕ Class** | Shift curriculum class **back or forward** for this group |
| **✕ Cancel** | Cancel the group’s sessions |

**↕ Class (important):**  
Example — group is on Class 5 but needs to redo Class 2:

1. Tap **↕ Class** → choose **Class 2** → confirm.  
2. This session now teaches **Class 2**.  
3. Earlier Pass marks for Class 2 and later become **Outdated**.  
4. After you score a **Pass** on this session, the next class becomes **Class 3**.  

Moving **forward** (e.g. jump to Class 5) marks skipped earlier classes as passed (assumed), outdates Class 5+, and this session teaches Class 5 (next = Class 6).

Then open the group scorer and mark attendance / scores as usual — **this session’s score** is what counts.

### 4.5 Reflection (optional)

- Add session notes, photo/video links where the reflection button is shown.

## 5. Staff

**Purpose:** Daily attendance and HR basics for grooms and yard staff.

### 5.1 Default = Present

- Everyone active is **Present by default** for **today**.  
- You only tap **Absent** if they did not come.  
- **Once marked Absent, you cannot switch back to Present** for that day (other buttons are disabled). Contact admin if it was a mistake.

### 5.2 Mark attendance

| Button | When to use |
|--------|-------------|
| **Present** | They are at work (usually already default) |
| **Absent** | Did not come today — **locks** the day |
| **Leave** | Pre-approved leave (deducts leave balance) |

### 5.3 Add new staff

1. **+ Add staff / groomer**  
2. Fill name, mobile, designation (Staff / Groomer), joining date, etc.  
3. **Save**

New staff get **4 leave credits per month** (automatic).

### 5.4 Apply leave (date range)

1. On the staff card → **Apply leave range**  
2. Start date, end date, reason → **Apply leave**  
3. Leave balance reduces automatically for those days.

### 5.5 Edit staff details

- **✎ Edit details** — uniform issued date, bank details, photo, etc.  
- **Remove** — marks inactive (history kept); confirm with admin before removing.

### 5.6 Change date

- Use **Attendance date** at top to view or mark past days.  
- Past days with no mark may show as **Absent** (not default Present).

## 6. Riders

**Purpose:** Look up registered riders and training progress.

**Actions:**
- **Search** by name, KE number, phone.  
- Filter by grade, section, level if filters are shown.  
- Open rider cards for progress / makeup / curriculum detail (where available).

**Adding riders:** School riders normally come from the **registration form** (parents). Trainers usually **do not** create riders manually unless admin asks.

## 7. Feed

**Purpose:** Track hay, pellets, bran, supplements — quantity on hand and daily use.

### 7.1 Two types of feed item

| Type | When to choose | What you do |
|------|----------------|-------------|
| **Regular** | Fed every day (hay, pellets) | **Log today** each evening; system can estimate missed days |
| **Occasional** | Vitamins, special supplements | **Log use** only when used — **no** daily auto-estimate |

Set type when **adding** or **editing** feed (**How is this used?**).

### 7.2 Add a new feed item

1. **+ Add feed** (or “Add your first feed”)  
2. Name, location, starting qty, unit (bags/bales/kg), minimum level  
3. **Regular:** enter expected use per day  
4. **Occasional:** leave daily use at 0  
5. Optional: **weight of one unit (kg)** — allows logging in kg later  
6. **Save**

**Note:** Unit (bags vs bales) **cannot be changed** after save — pick correctly the first time.

### 7.3 Daily actions (Regular feed)

| Button | Action |
|--------|--------|
| **Log today** | Record how much was fed today (one entry per day) |
| **+ Stock in** | New delivery arrived |
| **Record stock count** | Physical weigh/count — required if banner says “Stock count needed” |
| **Confirm / edit X day(s)** | Accept or fix **estimated** days you forgot to log |
| **History** | Last 10 movements |
| **✎ Edit** | Change name, min level, usage type — not starting qty |

### 7.4 Occasional feed (vitamins etc.)

| Button | Action |
|--------|--------|
| **Log use** | Used amount; optional **horse** name |
| **Expire** | Thrown away / expired |
| **+ Stock in** | New stock received |

### 7.5 Stock count banner (important)

If you see **“Too long without an entry — please weigh what is left”**:
- Do **not** only confirm estimates.  
- Use **Record stock count** (Adjust) with the **actual** amount on hand.  
- This resets trust in the figure after a long gap (14+ days).

### 7.6 Accept all estimates (use carefully)

- Banner **Accept all estimates** — only if every estimated day is roughly correct.  
- Prefer **Confirm / edit** per item if any day was different.

## 8. Tack

**Purpose:** Saddles, bridles, helmets, boots — quantity by location.

### 8.1 Add tack item

1. **+ Add tack**  
2. Name, category, model, vendor, location, qty, min level, photo optional  
3. **Save**

### 8.2 Movements

| Button | When |
|--------|------|
| **+ Stock in** | New items received |
| **Wear out** | Damaged / discarded — add reason; photo optional |
| **Transfer** | Moved to another location/storage |
| **History** | Last 10 entries |

### 8.3 Filters

- **Low stock**, **Out of stock**, search by name/location/category.

## 9. Horses

**Purpose:** Stable register, health care, lease, and activity timeline.

### 9.1 Add a horse

1. **+ Horse**  
2. Fill identity (name, chip, EFI), trainer, groom, status, breed, DOB, photo  
3. **Health:** Vaccination, Deworming, Farrier — status **Done / Not Done / Postponed** + dates  
4. **Lease:** rider name + date if leased out  
5. **Save**

Age is calculated from date of birth automatically.

### 9.2 Built-in care (on Edit horse)

- **Vaccination**, **Deworming**, **Farrier** — update status and date when work is done or postponed.  
- Saving the horse writes to the **Activity** log when something changed.

### 9.3 Extra care types (shoeing, dental, booster…)

**One-time setup (stable manager):**
1. **+ Care type** (top bar)  
2. Enter name (e.g. *Shoeing*) and typical interval in days (optional)  
3. **Save** — now available for all horses  

**Per horse:**
1. On horse card → **+ Care**  
2. Choose activity, status, date done (or postponed date)  
3. **Save**

### 9.4 Activity timeline

- **Activity** button on horse card — care, lease out/return, status changes, newest first.  
- Full search → **History** tab, filter **Horses**.

### 9.5 Lease

- Edit horse → **Lease** section: rider name + lease date.  
- Clearing lease rider = horse returned.  
- Both log to Activity.

### 9.6 Retire a horse

- **Mark retired** — horse stays in system but status = Retired (filtered out of active list).

### 9.7 Filters

- Status: Active, Leased, Rehab, Lame, Retired  
- Care: overdue, not done, status unconfirmed  
- Search: name, chip, trainer, etc.

## 10. History

**Purpose:** Find anything that happened across feed, tack, horses, staff, sessions.

1. Open **History** tab.  
2. Default: **last 30 days**, all areas.  
3. **Area** filter: Feed, Tack, Horses, Staff, Sessions.  
4. **From / To** dates — widen or narrow.  
5. **Search** box — horse name, staff, feed item, etc.  
6. **Apply** or press Enter in search.

Card-level **History** buttons (feed/tack) show only the **last 10** entries for speed.

## 12. Rules and limits (important)

1. **Staff Absent is locked** for that day — double-check before tapping.  
2. **Feed units** (bags/bales) fixed after create — use Stock in / count for qty changes.  
3. **One consume log per day** per Regular feed item — use Adjust/count to fix mistakes.  
4. **Occasional feed** — no daily reminder; you must **Log use** yourself.  
5. **Horse Activity** shows events when you save changes — not a duplicate of the care due dates on the card.  
6. **Do not share login** — each trainer has their own username.  
7. **Campus URL** — use only your location’s link (Hyderabad / Pune / Bangalore are separate).

## 13. If something goes wrong

| Problem | Try this |
|---------|----------|
| Blank screen or error on open | Hard refresh (Ctrl+F5); ask admin to check deployment |
| “Session expired” | Log out and log in again |
| Cannot mark staff Present after Absent | By design — ask admin to fix in sheet if wrong |
| Feed “needs confirm” will not go away | Confirm days OR record actual stock count |
| Payment / registration | **Not in this app** — parents use Google Forms; ask office admin |
| Missing welcome email / receipt | Office admin — not trainer action |
| Wrong horse care in Activity | Save horse again after updating dates; open Activity |
